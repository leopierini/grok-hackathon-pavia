## Behavior

The parser accepts the eight operator commands and nothing else. `arrived` requires one of `entrance`, `room_2`, or `display`. Empty text, extra arguments, control characters, shell metacharacters, and input longer than 256 characters are rejected. Rejected text is not queued and does not call a device or change the trusted zone or target.

`halt` calls `kernel.authority.latch_cancel` on the input path, before a blocked command consumer finishes. A `flight-ready` in the same logical turn is rejected whether it is written before or after `halt`. A readiness result that was already returned stays as it was; the latch rejects the next confirmation.

Arrival and readiness waiters are created only when `confirm` is called. They are keyed by mission, epoch, stage, kind, and zone. An `arrived` entered before that call, for another zone, or again after success is rejected and is not reused. A manual-clock deadline that passes returns `expired`. A session snapshot from an older epoch returns `stale`.

`quit` and EOF publish `shutdown_requested`. Ctrl+C and EOF also latch halt. `reset` publishes `reset_requested` and does not latch. This service does not run Task 29's application shutdown. A failing status writer cannot stop the halt latch.

Scripted lines and a `prompt_toolkit` pipe with `DummyOutput` produce the same command names. The default path does not import `termios` or `tty` and does not call `add_reader` or `add_signal_handler`. `close` is idempotent and cancels the input and confirmation tasks it started.

## Extra edge cases

- `flight-ready` does not satisfy an arrival waiter, and `arrived entrance` does not satisfy a `room_2` waiter.
- A second `confirm` for the same family replaces the previous waiter with `stale`.
- After a successful `flight-ready`, a later `halt` still latches, and the following readiness call returns `cancelled`.
- An input-error signal is recorded without starting a thread.
- A renderer exception during halt is counted and does not clear the latch.

## Limitations

- Pipe input covers Ctrl+C and EOF in process. The physical demo terminal was not used.
- Phase gates such as `WAIT_ARRIVAL` and `PREFLIGHT` belong to later features. This service only resolves the waiter that is open now.
- `quit` does not close adapters or exit the process.
- Confirmation deadlines use the kernel clock. The responsiveness check around a held model call uses the event-loop clock and stays under half a second in this run; that is not a hardware halt measurement.
