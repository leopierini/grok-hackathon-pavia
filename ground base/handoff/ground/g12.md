## What Ground will believe

A flag becomes true only when the owning peer reports it as boolean `true`, `validated` is `true`, and `acceptance_evidence_ref` is a non-empty string. A string such as `"true"` is rejected. `controlled_motion: false` stays false even when `supported_commands` lists takeoff or `move_local`.

The bundled simulated examples arm this set. It is not a motion grant. `session_armed` and `motion_permission` stay false.

| Peer | Device | Armed flags |
| --- | --- | --- |
| Drone | `drone-01`, Tello EDU, `synthetic-test-v1` | `controlled_motion`, `downward_video` |
| Dog | `dog-01`, Unitree Go2 PRO, `synthetic-test-v1` | `controlled_motion`, `lidar`, `slam`, `target_range` |
| Pi | `pi-01`, Raspberry Pi (model unconfirmed), `synthetic-test-v1` | `rssi_receiver` |

Top-level `controlled_motion` is the **drone** flag and is what autonomous search checks. Dog motion is `dog_controlled_motion`. The back router is `router-back` with networking `failed`. It is not a peer and it does not change the Pi record.

Commands Ground will require before arming a claimed feature:

- Drone `controlled_motion`: `takeoff`, `search_step`, `track_step`, `hover`, `land`
- Dog `controlled_motion`: `stand`, `move_local`, `turn`, `halt`
- Pi `rssi_receiver`: `read_window`

`downward_video` also requires camera id `downward`. Without that id the report can still be accepted, and the flag stays false with reason `downward_camera_id_missing`.

## Extra edge cases

- `validated: false` keeps the reported feature map and arms nothing for that peer.
- `acceptance_evidence_ref: null` disarms that peer even when `validated` is true.
- A batch that contains one invalid report stores none of that batch.
- The same new report repeated inside one batch stores one record.
- Role `vision`, a router device id, a source that disagrees with the role, and `simulated: false` combined with the synthetic evidence reference are rejected.
- An already armed snapshot, a halt latch, a cancelled authority, and a dog-transport profile that disagrees with `GroundSettings.dog_transport` do not grant motion.
- A stale replay of an old epoch does not refresh the new session.

## Limitations

- `expires_at` on a capability report may be null or a non-empty string. This card does not compare it with the clock. Epoch is the staleness check.
- Missing peers are reported in order: drone, then dog, then Pi. One reason is returned.
- Nothing here measures the Tello, the Go2, or the Pi. A true flag in a simulated fixture is not physical acceptance.
- This machine ran CPython 3.12.10. Mypy used `python_version = 3.11`.
- `python -m patrol.ground.sim --task 12` cannot succeed until the senior's Gate C loader accepts `ground-task-v2` and `feature.v2_capabilities`.
