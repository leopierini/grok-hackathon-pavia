## Message kinds

- Input: `motion.proposal` for the drone, or an operator request for one of `takeoff`, `search_step`, `track_step`, `hover`, `land`.
- Output: `drone.command`, or a rejection with a stable reason and no command.
- The example proposal `proposal-drone-001` becomes `track_step` / `verified-left-step-v1` when control, calibration, and the primitive are present. The command envelope matches `ground-to-drone-command.json` at `2026-11-04T13:00:10.210Z`.
- Hover matches `ground-to-drone-hover.json`. Land matches the payload of `ground-to-drone-land.json`. Its `lease_ms` stays 500. Its operation deadline is the fixture landing deadline, 8000 ms, so `expires_at` is `2026-11-04T13:00:19.000Z` rather than the example's 500 ms envelope.
- Command acknowledgements are left to Task 18. This card does not advance the beacon epoch; it copies the current epoch onto the command. The example command uses epoch 4 while the proposal still says 3.

## Behavior

One approval allocates one `command_id`. The same proposal id returns that record, including when the replay copy contains SDK text. A different proposal id allocates a different command. A rejection is not cached.

`search_step` and `track_step` require `controlled_motion` to be the boolean `true`, a validated armed report, and `lease_ms` of at most 500. The issued lease is the primitive's lease. A requested lease of 5000 is rejected. Takeoff and land use `takeoff_deadline_ms` and `land_deadline_ms` from the allowlist. A deadline of 500 ms or less is rejected so the motion lease is not a motor-cut timer.

When `controlled_motion` is false, track, search, and takeoff are rejected. Hover and land still issue their own primitives. An operator search marked `supervised: true` issues `operator-supervised-step-v1` and is labeled operator-supervised. The same label is rejected while controlled motion is armed.

A track step requires calibration `true` and a non-empty `camera_to_body_calibration_id`. Null calibration blocks the step. The command copies the evidence frame id, track id, and current beacon epoch. Image direction selects an allowlisted primitive. It is not converted into a body yaw.

A search step draws the next id from the seeded allowlist with `random.Random(seed)` and stops at `step_cap`. Seed 0 selects `verified-search-right-v1`. It does not call an unbounded random move.

Requested height is copied only when the profile lists that height and the observation reference is the same. The observation's 4 m reading is not copied onto a track step. Height 4 with reference `unknown` is rejected. Height 4 is also rejected when the profile allows nothing.

A dog proposal, SDK text, a five-meter string, an expired proposal, a missing primitive, an airborne takeoff, an unknown flight state, an active command, and a string `"true"` do not produce a command. After halt, track is cancelled and land is still issuable. A ticket from the previous epoch is `stale_ticket`.

## Extra edge cases

- `"true"` does not arm `controlled_motion`.
- Direction `right` has no track primitive, so the proposal is `primitive_missing`.
- Takeoff while the observation says airborne is `already_airborne`. Takeoff from `grounded` with an agreed `floor_agl` profile copies 4 m and still uses the 8000 ms takeoff deadline.
- `flight_state` `unknown` blocks a track and still allows land.
- A latched halt blocks a new track and still allows land. Land does not call `drone.land`.
- A ticket from the previous epoch is rejected before a new land command is stored.
- `active_command_id` blocks a new primitive.
- A landing deadline of 500 ms is `deadline_reuses_motion_lease`.
- A supervised search while control is armed is `supervised_conflicts_with_control`.
- Search seeds 0 through 20 stay inside the two allowlisted search primitives.
- Replaying a poisoned copy of an approved proposal id does not allocate a second command.

## Limitations

- This machine ran CPython 3.12.10. Mypy used `python_version = 3.11`.
- `python -m patrol.ground.sim --task 17` cannot load the required v2 manifest on the merged Tasks 01–10 loader. The in-process harness covers the same cases. Gate C has to admit `ground-task-v2` before that CLI succeeds. Adding this manifest also makes `python -m patrol.ground` fail closed at discovery instead of listing missing providers.
- Nothing here flies a Tello, opens UDP, or imports DJITelloPy. Lease and deadline numbers are fixture limits, not measured motor times.
- The provider does not turn image left/right into a yaw command and does not read acknowledgements.
- Omitting `evaluated_at` uses the kernel clock. The manual clock starts at 2026-01-01, which is before the example expiry. A real clock after `2026-11-04T13:00:10.700Z` rejects that example unless the caller pins `evaluated_at`.
- Idempotent replay returns the first approval and does not re-check a later, worse copy of that same id.
