## Behavior

`execute` reads one dog observation, one navigation-candidate envelope, one armed capability report, the current map epoch, and the selected dog transport (`ethernet` or `wifi`, from `profile` or `GroundSettings`). It returns a readiness record (`standing`, `stationary`, `avoidance`, `navigation_mode`, `slam_state`, `minimum_clearance_m`) and the candidate ids that are safe, in `dog/base_link`, unexpired, and on the current map epoch. Ids stay in the dog's order. Deltas are not turned into a command.

`ready` is true only when posture booleans are true, transport matches the profile, the pose is valid, and at least one candidate remains. `slam_local_planner` also requires armed slam and `slam_state=localized`. `reactive_avoidance` does not require slam. Null is not treated as true. A string such as `"true"` is `invalid_input`.

`blocked: true` with an empty list is a successful observation: `ready` is false, `ready_to_wait` is true, and the candidate list stays empty. A blocked list that still contains candidates is rejected. No detour is synthesized.

`slam_local_planner` while `features.slam` is false, or while `validated` is not true, is `rejected`. A candidate that carries a target range is `rejected`. `minimum_clearance_m` stays on the readiness record and is not copied into a target-range field. The capability flag `features.target_range` is not a measured distance.

The front-camera frame object is copied through. Its `image_ref` is not opened. No adapter method is called. Result `commands` is empty and `motion_proposed` is false. A cancelled or stale ticket returns no candidate ids.

## Extra edge cases

- `blocked: true` with a non-empty list is rejected. An unblocked empty list stays empty (`no_candidate`), not a synthetic forward step.
- `valid_until` equal to the kernel clock is dropped. Only a strictly later deadline is usable.
- A candidate map epoch that disagrees with the pose, the candidate envelope, or the current map fixture is dropped.
- A body frame other than `dog/base_link`, `safe: false`, and a mismatched snapshot id are dropped.
- Safe ids keep the dog's order. Unsafe ids are omitted and the rest are not reordered by delta.
- `safe: "true"` is invalid. It is not coerced.
- Duplicate candidate ids are invalid.
- Observation and candidate `navigation_mode` must match. `reactive_avoidance` with slam disarmed and `slam_state=not_available` can still publish a safe id.
- `slam_state=lost` withholds the step. `standing: false`, `stationary: false`, and `avoidance: null` withhold it. Null standing also prevents `ready_to_wait`.
- Unvalidated capabilities disarm slam and lidar.
- A non-empty list without `lidar_observed_at` or `minimum_clearance_m`, or with lidar disarmed, fails validation and publishes no id.
- Ethernet observation against a wifi profile, including `GroundSettings.dog_transport`, is not ready. Wifi against wifi is ready. Conflicting profile and settings are invalid.
- Device mismatch is `contract_mismatch`. A cancelled ticket and a stale ticket publish nothing.
- An observation field named `target_range_m` is rejected. The capability `target_range` flag is not copied into the result.
