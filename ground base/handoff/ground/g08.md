## Behavior

The gateway builds one dog, one drone, and one reasoner per lifecycle and records a process-wide owner. A second build, or a second gateway, is rejected while that owner is live. Ethernet and Wi-Fi are two profiles of the same DogPort; the selected profile changes only after close, and the dog config `transport` must match `settings.dog_transport`.

`invoke` allowlists contract methods. `takeoff` and other vendor commands are `forbidden_command`. Ordinary calls re-check the ticket, cancellation, and deadline immediately before the device call. `halt` and `land` may still run after cancellation when the ticket belongs to this lifecycle. A call that finishes after `close` bumps the generation is discarded and does not become `last_invoke`.

Connect and status return `ComponentSnapshot`. Unknown booleans and `flight_state="unknown"` are copied through. `device_sample_time` is always null. `observed_at` is the gateway clock when the response was observed. A drone that is disconnected at the first connect is `optional_unavailable`. The same drone later reporting disconnected is `active_link_loss` and `recovery_required`. Snapshots include the evidence gaps the contract cannot prove: SDK capability, worker quiescence, telemetry freshness, device timestamps, `workers_idle`, and `reset`.

`close` calls dog, drone, and reasoner even when an earlier close raises. The raised detail keeps the primary operation fault plus every close failure. A second `close` repeats that detail and does not call the adapters again. Recreation is rejected while a shielded worker is still running, including after the outer invoke task was cancelled. Once that worker finishes and close did not fail, a new build is allowed.

## Extra edge cases

- A string such as `"yes"` in a dog posture field is `contract_mismatch`, not coerced to a boolean.
- A factory that returns a string, or a connect result that is not `DogStatus`, fails at the boundary.
- The fenced `RunContext` must be the same object passed to the device method.
- Public resolution ignores stub callables sitting in the same resolver mapping.
- A dog profile whose config transport disagrees with `dog_transport` is `invalid_input` before any factory runs.
- A failed close blocks a later build with `failed close blocks recreation`.
