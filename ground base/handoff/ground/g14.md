## Interface

`patrol.ground.extensions.g14.implementation:create(services) -> FeaturePort`

```text
async execute(request: FeatureRequest) -> FeatureResult
```

Manifest schema `ground-task-v2`, slot `feature.v2_frame`. Construction does not read files or call peers. A stage request named `feature.v2_frame` checks one frame. The Task 01 harness calls the same provider with `kind="diagnostic"` and a case name; that result uses only `kernel.foundation` data keys so the existing simulator can score it.

An accepted result carries `camera_id`, `camera_epoch`, `captured_at`, and the `artifact://` reference. The bytes stay in the store. The proposed event is `frame_validated` or `frame_rejected`. Nothing in this provider calls the adapters, the state port, or a vision request.

## What acceptance means

- `camera_id` is `front` or `downward`. `rear`, `back`, empty, and any other id are rejected. Downward is not relabeled as a rear camera.
- Width and height are positive integers and match the decoded JPEG. The downward fixture is 320×240 and the front fixture is 1280×720. Another positive size is accepted when the bytes match and the camera epoch moves with the change.
- `sha256` is 64 lowercase hex digits and equals the resolved bytes. One flipped hash bit is rejected.
- `artifact://` resolves only inside the task store. A Windows path, a backslash, or a `..` segment is not an artifact on another machine.
- `simulated: false` is rejected when the bytes are one of the bundled synthetic images (`placeholder.jpg`, the downward fixture, or the front fixture). A different JPEG may be labeled real.
- A camera switch, resolution change, or calibration change must arrive with a strictly newer `camera_epoch`. The same camera may keep its epoch. An older epoch is rejected. If the snapshot epoch or the frame epoch changes while validation is paused, the result is `stale_epoch`.
- `camera_to_body_calibration_id: null` is kept and marked `uncalibrated`.
- The baseline evidence port checks the JPEG marker, the source, the zone, and that the file stays inside the store. Pillow then checks that the decoded size matches the claim. Text renamed to `.jpg` is rejected.
- `captured_at` is the frame string. File modification time is not copied over it.
- A file that is missing, disappears between the two reads, or changes between those reads fails closed. No handle is returned.

## Extra edge cases

- Uppercase and short hashes, a string `"false"` simulation flag, and width `0` are `invalid_frame` or `invalid_input`. They are not coerced.
- A naive capture timestamp is `captured_at`.
- An unknown frame field such as `sdk_command` is rejected before any read.
- A `SessionSnapshot` evidence map is accepted as the previous camera epoch.
- The same epoch is allowed when the camera, size, and calibration are unchanged. A lower epoch is rejected.
- A unique 8×6 JPEG that is not in the placeholder set can be `simulated: false` after the epoch moves.
- A halt that is already latched returns `cancelled` and no handle.
- Rejection data does not echo a sender Windows path.
