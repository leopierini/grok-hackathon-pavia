## Behavior

The scheduler emits at most one `vision.request` at a time, from the newest frame that is still inside the evidence budget. Defaults are sample 1000 ms, timeout 5000 ms, evidence age 3000 ms, and max in flight 1. A burst in one call becomes one request for the newest fresh frame. Frames that arrive while a request is in flight, or before the sample interval has elapsed, are held; an older held frame is dropped when a newer one arrives.

`expires_at` is the manual clock plus the configured timeout. `max_evidence_age_ms`, the artifact reference, camera id, camera epoch, and capture time are copied from the frame and settings. Provider is `xai`. `CONFIGURE_VERIFIED_IMAGE_MODEL` is copied unchanged and `model_unresolved` is true. A timeout retires that `request_id`. It does not send the same id again. The next accepted frame gets a new id and the same `frame_id`.

Stages are `drone_search`, `drone_track`, `dog_acquire`, and `dog_approach`. The last three require `active_track_id`. `drone_search` accepts null. Drone stages require the downward camera. Dog stages require the front camera. Scene context is copied from settings. Target text that asks for criminal intent is rejected. `image_ref` must be an `artifact://` URI.

No dog, drone, reasoner, journal, or socket call is made. A latched cancellation or a stale ticket blocks emission.

## Extra edge cases

- A frame aged exactly 3000 ms is still fresh. 3001 ms is dropped.
- A second frame at 1500 ms is still held, because the first request has not timed out.
- An older frame does not replace a newer held frame.
- `clock_error_ms` of 3000 does not block. 3001 blocks emission of a fresh frame.
- A frame timestamp ahead of the ground clock is rejected.
- A held frame that ages past the budget is dropped at the next sample and is not sent.
- After the default 5000 ms timeout, the original frame is older than 3000 ms, so it is dropped and the old request id is not reused.
- The new-id retry is covered with `timeout_ms` 1000, which is still inside the 3000 ms evidence budget.
- An epoch change retires the in-flight id and the next request uses a new id.
- `max_in_flight` other than 1, a string boolean, a missing model id, a local path, an `https` URL, and an extra frame field are rejected.
- A configured model id that does not start with `CONFIGURE_` is copied and marked resolved. It is still not called.

## Limitations

- The official `python -m patrol.ground.sim --task 15` command cannot load this manifest until Gate C admits `ground-task-v2`. The 12-case harness result above is the simulation evidence.
- v1 `GroundEvent` kinds cannot name `vision.request`. The message is the result payload, not a session event.
- `clock_error_ms` is not added to the measured frame age. Only an uncertainty larger than the whole evidence budget blocks a fresh frame. An omitted value is treated as 0 for simulation. A real run has to pass the negotiated clock error.
- The default 5000 ms timeout is longer than the 3000 ms evidence budget. A frame captured at the start of that request is stale when the timeout fires. That is intentional: the old request is unusable, and it is not silently replaced.
- Image bytes, the hash check, and the xAI call are not done here. Task 14 owns bytes. Task 16 owns `vision.decision`.
- Nothing here measures xAI latency, Tello video delay, or Pi clock error. Budgets are the demo starting values, not tuned hardware limits.
- This machine has CPython 3.12.10 only. Mypy checks with `python_version = 3.11`.
