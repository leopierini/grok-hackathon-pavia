## Interface

`patrol.ground.extensions.g06.implementation:create(kernel, peers) -> EvidencePort`

```text
async validate(frame, *, expected_source, zone, mode, output_root, interval) -> EvidenceResult
```

Construction does not read files or call peers. A rejected result has `frame=None`, so it cannot be forwarded. The original `captured_at` string is never rewritten.

## What acceptance means

A live dog or drone JPEG is accepted only when all of these hold:

- It is a real `Frame` whose source, zone, and boolean `simulated` flag match the call.
- The path is absolute, a regular file, and its resolved location stays inside the adapter output directory.
- The bytes decode as a JPEG within the size and pixel limits (default 8 MiB and 8,000,000 pixels).
- The capture time is timezone-aware UTC, not after the kernel clock, and inside the operation interval, including both endpoints.

A phone image may use `captured_at=None` (`time_origin=unknown_phone`) or a supplied UTC timestamp. Copying the file does not turn the file's modification time into a capture time. An operation interval passed with a phone image is ignored (`phone_interval_ignored=true`).

Landing delay is not treated as a stale frame. An aerial capture 12 seconds before validation is accepted when it sits inside the inspect interval. A dog frame 6 seconds old is also accepted when it is inside its interval. `five_second_return_rule_applied` is always false, and `stream_selection_freshness` is always `not_claimed`.

## Extra edge cases

- The string `"false"` is rejected as `invalid_simulation_flag`. It is not coerced with `bool(...)`.
- A real adapter returning `simulated=True`, and a fake adapter returning `simulated=False`, are both `simulation_mismatch`.
- `..` traversal and a file that merely lives outside the output root are `containment_escape`, and the file is not read.
- A directory path is `not_regular_file`.
- Empty, truncated, non-JPEG, oversized, and over-pixel images are rejected with distinct reasons. A PNG header renamed `.jpg` is `not_jpeg`.
- A file that disappears or changes between the two reads is `disappeared` or `changed_during_validation`.
- Injected slow read and slow decode keep the event loop free. Measured halt-pulse latency in those cases stayed under the 0.5 second fake target.
- A kernel clock set three hours behind a capture time yields `future_timestamp` and leaves the original string in place.
- Naive, malformed, blank, and missing live timestamps are rejected before they can authorize a later stage. A missing, inverted, or naive interval is `missing_interval` or `invalid_interval`.

## Freshness that this port cannot prove

Ground can check file integrity and the timestamp's relationship to the operation interval and the kernel clock. It cannot prove that the adapter picked a fresh stream buffer. The five-second selection rule remains adapter-owner acceptance evidence. A dishonest timestamp that still falls inside the interval is not detectable here. File modification time and JPEG EXIF are not used as capture time.
