## Behavior

One ordered journal is measured on one monotonic domain. A missing endpoint is null and names a reason. An empty journal is null for every measurement, including counts, and the reason is `empty_journal`. It is not a row of zeros. Denominators still report how many records were supplied, so an empty journal has `journal_records: 0`.

Unknown landing (`landing_unverified`, or a land acknowledgement that is not verified) keeps goal-to-landing null with reason `landing_unverified`. A later completed acknowledgement does not erase that. A completed acknowledgement for a different command id is not a landing.

Removing the dog-camera decision nulls only `dog_activation_to_dog_camera_s` (`dog_camera_acquisition_missing`). Detection, hold, and the earlier intervals stay filled.

Two monotonic domains in one subtraction fail the request with `rejected` and name both domains. No duration is returned. A peer monotonic field on the same record is ignored.

Vision latency uses monotonic milliseconds when both the request and the decision have them. The copied vision examples have only `sent_at`, so those pairs use UTC when `utc_pairs_allowed` is true. The drone example pair is 0.1 s. A stale dropped frame increments the drop count and is not reported as a fast latency. If that frame id was also decided, the pair is null with reason `stale_frame_dropped`.

Beacon-epoch changes count as one reset per record. An explicit `beacon_epoch_reset` on the same record is not counted twice. RSSI windows are counted by the `quality` string. `blocked: false` is not a blocked-candidate event. Model accuracy stays null with `no_labeled_evaluation` unless an evaluation manifest is supplied. A successful scripted mission does not fill accuracy.

Recomputing the same journal returns the same result. Secret field names (`api_key` and the other denylist names) are listed in `rejected_fields` and their values are not copied. A string such as `"true"` is rejected. A cancelled ticket is rejected before measurement.

The result carries no `GroundEvent`. The v1 event allowlist is a session-transition list, and applying one of those kinds would change mission phase. The metrics live in `FeatureResult.data` until Gate C adds a projection event.

## Extra edge cases

- A duplicate `message_id` keeps the first target time and increments `journal_records` without incrementing `records_used`.
- A dog decision whose track id differs from the drone target is `track_mismatch`, and detection stays filled.
- `blocked: false` on the copied candidate list does not increment the blocked count.
- A monotonic value stored for another device is not subtracted from the ground clock.
- A dropped frame with the same id as a vision decision nulls that latency.
- An airborne completion for a non-land command does not become a landing time.
- `events` is accepted as an alias of `journal`.
- A journal string, a non-boolean clock flag, and a cancelled ticket are rejected.
