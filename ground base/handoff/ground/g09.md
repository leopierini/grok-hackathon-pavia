## Behavior

One mission coroutine runs the frozen stage order. Input supervision and a health hook run beside it. Device and model calls go through the executor and adapter ports. Feature slots are resolved from the kernel registry.

Dismiss skips prepare, route, capture, and flight, and publishes one template report. Ground-clear and ground-confirmed resolve without `drone.inspect`. Blocked-resolved inspects once, keeps the flight lock, and does not set recovery when landing is grounded. Unknown landing enters `FAULT` with recovery latched; the report does not emit `recovery_cleared` and does not call final wording.

Missing dispatch or preflight blocks that stage. Missing restart blocks motion. A missing transport, metrics, or status provider does not block flight; transport then uses the built-in guard. Real motion requires arming. A fake dog cannot authorize a `dog_pad` launch. A manual clock cannot build a real-adapter deadline. An initial preflight that returns `may_inspect` does not continue to flight-ready or inspect.

Halt, persistence loss, and link loss latch safety before the next await. A late feature result after halt does not prepare the dog. A second `start` is rejected. A second terminal call does not publish again. Reset requires an explicit physical-recovery note and no pending worker.

The synthetic pack in `synthetic.py` is installed only by tests and by `execute`. Production `create` leaves the feature map empty.

## Extra edge cases

- Admission waits inside incident input; a halt that changes the epoch rejects the input and does not call `state.open`.
- An empty target is rejected before a session opens.
- A feature event with another mission ticket does not change phase.
- A string boolean such as `"true"` is rejected by the kernel as `invalid_input` before route execution.
- Halt-then-release and release-then-halt both stop the following stage.
- Two fixed-seed blocked-resolved runs produce the same stage trace, and input plus health tasks are collected.
