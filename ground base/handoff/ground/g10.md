## Behavior

`request` latches cancellation and invalidates ordinary tickets before any device body runs. It schedules one `dog.halt` task and one `drone.land` task, then one supervisor. A second halt returns the same handle and does not start another landing. Stop errors are collected independently. A bounded `observe` can report pending work without cancelling those attempts. Recovery uses the kernel clock, not a cancelled mission `RunContext`.

Reset requires `verified is True`, no pending retained task, and a fresh status read of stopped dog plus grounded drone. It closes dog, drone, and reasoner even when one close fails. Cleanup errors stay beside the original mission failure and do not recreate adapters. After a clean close it builds and connects dog and drone, then replaces the epoch and cancellation `Event`. The service stays disarmed and does not call `run_route`, `inspect`, or takeoff. A string such as `"true"` is rejected. `replay_route` or `replay_takeoff` set to true is rejected.

Shutdown uses the same supervisor. It does not close while a stop task is still running, and a second shutdown does not start another landing. It does not clear the recovery lock and it does not cut motors.

Stop, status, and close go to the injected device objects. `AdapterPort.invoke` rejects a cancelled ticket, so it cannot carry the stop. No `workers_idle` or `reset` method was added to the dog or drone ports.

## Extra edge cases

- A blank reason or a non-ticket does not latch.
- `observe` rejects a boolean or zero deadline, and a handle from another ticket.
- While the latch is set, the console double rejects arrival confirmation. After reset it accepts a new confirmation. The confirmation generation changes with the latch and again on reset.
- An expired ordinary deadline still starts both recovery actions.
- Link loss still starts both attempts and the snapshot says `delivery_not_assumed`. It does not say the stop was delivered.
- A late grounded status does not clear the lock. Reset is still required, and it succeeds only after the re-read is stopped and grounded.
- A worker that swallows cancellation blocks adapter recreation. `adapters.build` stays at zero.
- A dog connect failure after close leaves the latch and epoch unchanged and does not replay a route or takeoff.
- Halt recognition on `time.monotonic()` finished in well under 0.5 seconds. That number is not a physical stop time.
- `request` does not wait on the journal. The double's record list stayed empty at the latch.

## Limitations

- This machine has CPython 3.12.10 only. Mypy checks with `python_version = 3.11`. A 3.11 interpreter was not executed.
- The foundation dog and drone doubles return immediately from halt and land. Hang, error, and unknown-status cases replace those methods on the injected double. They are not physical fault injections.
- A failed reconnect can record one `adapters.build` before the connect error. The latch stays set and no route or takeoff is issued. Quiescence failure does not call build.
- Shutdown will not close devices while halt or land is still pending, because that would be a second command path. A later shutdown, after those tasks finish, closes once.
- Nothing here measures Go2 stop time, Tello landing, or link-loss delivery. Device command expiry and the staff controller remain outside this package.
