## Behavior

The provider reads a comparable RSSI window list and the dog's current `navigation.candidates`. It returns one `candidate_id` only when motion is allowed, the beacon hold is stable, no dog command is already active, the planner is not blocked, the exploration budget remains, at least two valid windows share one beacon epoch and one map epoch, the median change clears the fixture hysteresis, and the spatial change points at one safe `dog/base_link` candidate.

Otherwise it returns stop, hold, handoff, or review. A single valid window holds. A tiny change keeps the previous safe direction instead of flipping. Noisy, stale, unavailable, moving-beacon, empty, expired, ranged, and unaligned inputs do not create a step. Dog vision that already shows the same one track returns handoff. A `dog_dispatched` mission event is proposed only for a selection. Nothing in the result is a `dog.command`, and no dBm value is written out as meters.

## Extra edge cases

- A string `"true"` for `dog_motion_allowed` is invalid input, not permission.
- Median `0` with an empty sample list is rejected. No-signal stays a null median.
- A candidate that carries `range_m` is dropped and is not copied into the decision.
- Equal alignment picks the lexicographically smaller candidate id.
- A stronger signal at the same pose does not invent a heading.
- A gradient back toward the start can select only a backward safe candidate.
- Two vision tracks become review. Cancellation and a stale ticket cannot select.
- A blocked planner list is ignored even when it still contains a forward id.

## Limitations

- This is simulated fixture behavior. It is not a measured Pi RSSI run and it does not open a radio.
- The trend uses the oldest and newest windows in the fixture. It is not a fitted path.
- Hysteresis and the exploration budget come from the fixture. They are not a calibrated museum constant.
- A pure yaw candidate, with no translation, is not selected.
- `python -m patrol.ground.sim --task 22` cannot load the manifest until Gate C admits `ground-task-v2`. The provider tests do not depend on that registration.
