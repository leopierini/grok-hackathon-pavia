## Behavior

`execute` reads one injected probe. It does not open a socket, join or leave Wi-Fi, change routes, or move the dog.

Ready requires, in the same snapshot: dog, Tello, and internet up; dog and drone capability messages; an explicit Pi path (`wired`, `usb`, or `second_radio`) whose probe reaches the laptop; a Pi heartbeat; and the acceptance file for the selected transport. Ethernet reads `tether-acceptance.json`. Wi-Fi reads `wifi-acceptance.json` and does not use the tether. The published profile is `ethernet-tether` or `wifi-lan`.

The failed back-enclosure router is recorded as `back_enclosure_failed` and is not the Pi. A failed router beside a USB Pi path is still ready. A failed router does not explain a missing Pi path.

A mid-run `switch_to` or `fallback_transport` is rejected and the selected transport stays put. A dropped dog link clears ready, sets `request_safety` and `task28_latch` on the event, and does not latch cancellation itself. Route, firewall, service-install, and router-repair actions are rejected and not performed. Secret fields are not copied into the result.

A real-mode probe whose links are still simulated stays blocked. `physically_demonstrated` is published only when the fixture says so and the links are not marked simulated.

## Extra edge cases

- Wi-Fi without its own acceptance is blocked and does not borrow the Ethernet tether.
- A dog link that is down does not fall back to Wi-Fi.
- String `"true"` for tether acceptance is rejected.
- `tello_ap` is not a Pi path. A USB path that only joins the Tello AP does not count as a laptop route.
- A Pi link that is down blocks RSSI even when the path name is present.
- Internet down blocks the profile and does not request the Task 28 latch, because the run never became ready.
- Sequential single-link probes are rejected. One snapshot has to show dog, drone, Pi, and internet together.
- `repair_router` and an unknown firewall field are rejected. The router is not repaired.
- A direct `check` payload and the scripted Ethernet fixture return the same detail.
- A real probe is marked `simulated: false` only when every link is non-simulated and the fixture says `physically_demonstrated`.
