## Interface

`patrol.ground.extensions.g04.implementation:create(kernel, peers) -> Journal`

```text
async open(run_id, output_root) -> JournalResult
emit(record) -> JournalResult          # synchronous, no disk I/O
async flush() -> JournalResult
async publish(summary) -> JournalResult
async scan(output_root) -> JournalResult
async read(output_root) -> JournalResult   # alias of scan
async close() -> JournalResult
```

`create` does not create a directory and does not start a thread. `open` creates `artifacts`-style `<output_root>/<run_id>/` with `events.jsonl` plus empty `dog/`, `drone/`, `grok/`, and `input/` directories, then starts one writer thread named `ground-journal-<run_id>`.

The kernel's `GroundError` allowlist and `GroundEvent` kinds are the evidence-port set (`frame_validated`, `frame_rejected`). Persistence faults are returned on `JournalResult.fault_code` with a fixed `detail` string. The journal does not call safety, workflow, dog, drone, or the reasoner.

## Durability

`emit` only enqueues. Return metadata keeps the claims apart:

| `durability` | Meaning |
| --- | --- |
| `queued` | Accepted by the in-memory queue. Not yet written. |
| `flushed` | Bytes were written. `fsync` did not complete. |
| `synced` | `os.fsync` returned for those lines. |
| `published` | `summary.json` was replaced in the same directory. |
| `failed` | The call failed. `fault_code` says why. |
| `pending` | The writer thread is still running. `saved` is false. |
| `closed` | `close` joined the thread, or the journal was never opened. |

`synced` means `os.fsync` returned. A later power loss can still drop those bytes. The real `DiskWriter` fsyncs both the JSONL append and the summary temporary file before `os.replace`.

Queue policy is **reject-new** (`QUEUE_POLICY`). `emit` never blocks and never drops an event that was already accepted. The default cap is 32 accepted-but-not-durable events (`JournalLimits.max_queue`) and 4096 bytes per line. A full queue rejects the new event with `queue_full`. Two extra command slots, beyond that cap, hold one flush barrier and one stop so a full event queue can still be shut down. A line that fails before any byte is written is parked and retried on the next flush. A line that hits the file and then fails `fsync` stays flushed, is not rewritten, and is not counted as synced.

## Failure behavior

- `disk_full`, `permission`, and `closed_stream` during `open` return a fault and leave no run directory.
- The same codes during append leave the previous log bytes unchanged and keep the event queued for a later flush once the injected writer recovers.
- `rename` writes `summary.json.tmp` and leaves any previous `summary.json` in place. The result carries `prior_preserved`, the caller's `mission_error`, and `writer_error` as separate fields.
- A truncated final JSONL line is incomplete evidence. It is not counted as an event. A valid `summary.json` does not repair it. A missing or non-object summary is also incomplete. Scan diagnostics are fixed phrases and do not echo file contents.
- An existing run path is refused with `run_exists`, including an empty directory. A second process that only calls `mkdir` on that path fails.
- Run IDs must be a single safe token. `..`, slashes, and a missing output root are rejected before any write.
- An injected sanitizer runs on the caller side inside `emit`. If it raises, the result is `sanitizer_failed` and the exception text is discarded. This is not Task 27 redaction. Summaries are stored as the caller supplied them.
- `close` joins the writer for `close_timeout_s` (default 0.3s). A stalled thread returns `pending` and `saved=false`. A later `close`, after the write can finish, joins the thread and then reports `saved`.

## Extra cases covered

- `emit` before `open`, after `close`, and with a sequence that skips ahead.
- Concurrent `emit` calls produce sequence `1..n` with no gaps.
- An oversized record is rejected without copying the payload into the error.
- `time_to_arrival_s: null` survives publication.
- A symlink output root is rejected. Scan skips symlink children instead of following them.
- The provider source in `implementation.py` and `writer.py` has no `halt`, `land`, or `latch_cancel` call.
